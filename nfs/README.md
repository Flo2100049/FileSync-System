# Part 2: Network Job Executor (Socket-Based System)

## Περιγραφή
Το **Network Job Executor** είναι ένα κατανεμημένο σύστημα διαχείρισης και εκτέλεσης εργασιών (jobs) σε περιβάλλον δικτύου. Η αρχιτεκτονική του βασίζεται στο μοντέλο Client-Server χρησιμοποιώντας **TCP Sockets** για την επικοινωνία και ένα **Thread Pool** για την παράλληλη, ελεγχόμενη εκτέλεση των jobs στην πλευρά του server.

---

## Αρχιτεκτονική & Τεχνική Ανάλυση

1. **`jobCommander.c` (Client):**
   * Αναλαμβάνει τη λήψη των ορισμάτων από τη γραμμή εντολών, πραγματοποιεί τη σύνδεση (socket connection) με τον server και αποστέλλει την εντολή προς εκτέλεση.
   * Αναμένει την απάντηση του server και την τυπώνει στο standard output.

2. **`jobExecutorServer.c` (Server):**
   * **Main Thread:** Διαχειρίζεται τα arguments, αρχικοποιεί τα worker threads, ανοίγει το server socket και παραμένει σε infinity loop αποδεχόμενο νέες συνδέσεις από clients.
   * **Thread Pool & Synchronization:** Χρησιμοποιεί ένα Thread Pool με προκαθορισμένο αριθμό worker threads. Ο συγχρονισμός τους βασίζεται σε **2 Mutexes** (για την προστασία του buffer και του μετρητή ενεργών νημάτων) και **3 Condition Variables** (`κενός buffer`, `γεμάτος buffer`, `ενεργά worker threads`).
   * **Controller & Worker Threads:** Τα Worker threads παραμένουν σε αδράνεια όσο ο buffer είναι άδειος. Μόλις λάβουν σήμα, καταναλώνουν το job και το εκτελούν, σεβόμενα το concurrency limit.

3. **`Queue.c` (Thread-Safe Ουρά):**
   * Μια παραμετροποιημένη δομή ουράς (κυκλικός buffer) η οποία δέχεται το μέγεθος ως όρισμα κατά την αρχικοποίηση και παρέχει βοηθητικές λειτουργίες ελέγχου (π.χ. αν είναι γεμάτη/άδεια).

---

## Γνωστά Θέματα / Περιορισμοί (Known Limitations)
* **Διαχείριση Output Αρχείου:** Κατά την εκτέλεση ενός job, το αρχείο εξόδου (output file) δημιουργείται κανονικά στον server και αποθηκεύει επιτυχώς το αποτέλεσμα της εργασίας (καθώς και η διαγραφή του λειτουργεί χωρίς πρόβλημα). Ωστόσο, υπάρχει ένα θέμα στην επικοινωνία, με αποτέλεσμα ο client να μην λαμβάνει σωστά το περιεχόμενο αυτού του αρχείου για να το εκτυπώσει στην οθόνη του.

Στο project περιλαμβάνονται 3 αυτοματοποιημένα tests:
* **Test 1:** Έλεγχος όλων των βασικών εντολών και της συμπεριφοράς του συστήματος όταν δοθεί εντολή `exit` με μη άδειο buffer.
* **Test 2:** Δοκιμή οριακών καταστάσεων με buffer size = 3, ελέγχοντας αν ο server μπλοκάρει σωστά τις νέες εντολές (`issueJob`) όταν γεμίσει ο buffer.
* **Test 3:** Παρόμοιο με το Test 1, αλλά εστιάζει στην επιβεβαίωση της σωστής συμπεριφοράς και τερματισμού όταν ο buffer είναι εντελώς άδειος στο τέλος.

# *jobCommander.c
Κανει αυτα που ζηταει η εργασια. Περνει τα arguments σωστα κανει σωστη συνδεση με τον server και στελνει την εντολη που δωσαμε.
Και υστερα περιμενει για καποια απαντηση απο τον server και την τυπωνει.

# *jobExecutorServer.c
Για την υλοποιηση του buffer χρησιμοποιηουμε ουρα (η αντοιστοιχοι υλοιποιηση στην πρωτη εργασια). 
Εχουμε δυο mutex για τις κοινες μεταβλητες οι οποιες ειναι ο buffer και ο counter των ενεργων worker threads. 
Και εχουμε και 3 condition variables για οταν ο buffer δεν ειναι αδειος, οταν ο bufeer δεν ειναι γεματος και αλλο 
ενα για τα ενεργα worker threads. Χρησιμοποιω αρκετες global μεταβλητες οπως 
(αριθμος ενεργων worker threads, threadPoolSize, Concurrency, buffer, bufferSize, id για τα jobs, id του server socket) 
και μαζι και ενα struct που χρησιμοποιουμε για τα worker threads οπου μεσα εχει ως μεταβλητες 
το id tου client socket και το id του ιδιου του worker thread.

# Main:
Η main κανει τις αρχικες δουλειες δηλαδη χειριζεται τα arguments, δημιουργει τα worker threads, ανοιγει socket και μεσα σε ενα 
infinity while loop περιμενει για καινουργειες συνδεσεις απο clients.

# Controller thread:
Αναλογα με εντολη που τις δοθηκε κανει τις αντοιστοιχες ενεργειες οπως ζηταει η εργασια.

# Worker thread:
Στην αρχη ειναι σε ανδρανεια οσω ο buffer ειναι αδειος μεχρις οτου παρει σημα οτι δν ειναι, τοτε αν μπορει αρχιζει καιΣ εκτελει το job.
